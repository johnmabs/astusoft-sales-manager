# TASK-00-02-04 — Automate delivery documentation checks

**ID:** TASK-00-02-04
**Status:** in-progress
**Owner:** Project Maintainer
**Parent Epic:** [EPIC-00-02](../EPIC.md)

## 1. Objective

Extend documentation verification to detect structural,
referential and lifecycle inconsistencies in operational
delivery records.

## 2. Motivation

Manual reviews alone cannot reliably detect all broken
references and contradictory metadata as the repository
grows.

## 3. Scope

### Included

- File existence checks.
- Relative Markdown link validation.
- Delivery identifier validation.
- Duplicate identifier detection.
- Parent-child relationship checks.
- Parent inventory consistency.
- Official status value checks.
- Automated tests for the validator.

### Excluded

- Semantic approval of business decisions.
- Automatic Task completion.
- Automatic Git commits.
- Replacing the manual Gate review.

## 4. Dependencies and prerequisites

- **TASK-00-02-03:** Operational records available.

## 5. Applicable references

- **Contracts:** `docs/04-delivery/DELIVERY_CONTRACTS.md`
- **Statuses:** `docs/00-governance/STATUS_MODEL.md`
- **Existing tool:** `tools/check_governance.py`

## 6. Implementation plan

1. Review the existing governance validator.
2. Define validation rules for delivery records.
3. Write tests using representative valid and invalid
   Markdown fixtures.
4. Implement identifier and status checks.
5. Implement parent-child reference checks.
6. Implement inventory consistency checks.
7. Validate links without mistaking template placeholders
   for operational links.
8. Execute all validator tests.
9. Document usage and limitations.
